Why agent-ui

A framework shaped like the thing agents are good at

Agents write text and reason over explicit structure. agent-ui turns the interface into exactly that: a closed grammar, plain state and named actions, with the checks at the moment the page is written.

01

The UI is data

A page compiles to a JSON spec. The browser downloads the behavior and the finished spec, never the builders that assembled it.

02

State has one shape

Plain JSON in namespaces. Every write is an action, every action is logged, and a thrown error undoes the whole step.

03

Checks before guessing

Bindings, arguments, labels, list keys and URLs are validated on mount with a path and a fix. `agent-ui check` covers every page.

04

Server first

Every page renders on the server with its real URL and state. The browser takes over the markup the server wrote instead of building it again, and soft navigation replaces a page without a client-side router.

05

Small on purpose

No React, no build-time magic, no transitive dependencies. The grammar is closed, so there is one valid form of every part.

06

Written to be read

Readable names, no minification by the framework, and a cookbook of recipes that are tested on every run.

One page, two files

Behavior and content never mix

page.js declares the head, the namespaces and the plugins. view.js declares what the page looks like. Only the server and the build evaluate the view, so a browser never pays for the spec builders.

  • ✓state, derive and actions live in one namespace each
  • ✓handlers are [actionName, args], never logic
  • ✓lists have stable keys; ids are explicit
  • ✓network goes through resources, effects through plugins

page.js + view.js
export const page = {
  head: { title: 'Todos' },

// view.js

    li(null, item('text')),
  ),

Agent ready

Rules an agent can follow without a screenshot

The framework ships its own operating manual and a discoverable grammar. `agent-ui explain` prints the canonical recipe for a task, `agent-ui check` renders every page, and the runtime exposes state, actions and rendered structure as data.
