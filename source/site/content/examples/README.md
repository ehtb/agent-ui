# Examples

Each example is a standalone project with its own `package.json`, `build.config.mjs` and tests. Nothing is imported from outside its folder. The examples use the framework the way your project does: as an installed package, imported by name (`@ehtb/agent-ui`, `@ehtb/agent-ui/resources`, ...) and built with the `agent-ui` command. The dependency `"@ehtb/agent-ui": "file:../.."` links this repository into the example's `node_modules`. Copy a folder anywhere, change the dependency to a version, and it works.

| Example                      | Shows                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `basic`                      | The minimal page: `pages/page.js` (behavior) and `pages/view.js` (content) are `/`; two namespaces (`todos`, `filter`), one reading the other.                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `notes`                      | The quick start from `docs/API.md`: `notes` and `composer`, a cross-namespace `calls`. In memory: durable data belongs on the server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `contacts`                   | Forms and validation in four namespaces (`contacts`, `form`, `view`, `editing`); `calls` between them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `todomvc`                    | The official TodoMVC spec (minus persistence and routing, which do not apply) in four namespaces; a list of two handlers on one event; a benchmark; a user session run in the test shim and in real Chrome with the results compared step by step (skips without Chrome).                                                                                                                                                                                                                                                                                                                                             |
| `directory`                  | Two pages (`/` and `/person/:id`) sharing an async resource; URL parameters, nested lists.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `hydration`                  | Server rendering and takeover: every URL rendered per request, a 404 for an unknown article, `route.hydrated`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `registration`               | A complex form: fields that show, hide and fill each other, a collapsible panel, a country list and per-country regions fetched from the server, validation that follows what is on screen.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `react-converted-components` | A shadcn-style component library converted from React originals: variants, optional props, slots, field state as namespaces made by reusable features (the counterpart of custom hooks), mistakes refused with suggestions. A second page (`/primitives`) builds the interactive primitives React takes from a library — a popover with a focus trap, a combobox, a date picker and a drag list — as namespaces instead of component state. A third page (`/charts`) draws a Chart.js chart into one element with a plugin (`mountElement`), tested in headless Chrome; it depends on Chart.js from the npm registry. |
| `loading-states`             | Pages that say when they are ready: `ready`, `pending`, `status`, background refresh, a failed load as a finished state, 404 for an unknown id.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `orders`                     | A multistep flow: customer, then orders, then shipment, as chained resources across namespaces; a reusable `loadable` namespace; stale responses ignored; a validated form with notes kept in memory.                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `shop`                       | **Code splitting, and soft navigation.** Three pages (list, product, checkout) that share a shell (header and footer that stay while a `soft: true` link or `route.go` replaces the page; a real-Chrome test), components and a cart that lives on the server. Every page is its own entry, so a page downloads only what it imports and the code its pages share. Its README has the sizes (plain, gzip, esbuild, esbuild + gzip), what is downloaded once and what per page, the size of every module, how the split works and its limits.                                                                          |
| `events`                     | The largest example: one folder per page, per-page APIs from `compose-api.js` (a file to copy: the server side is plug-in, the framework only asks for an `api` object), different layouts, specific and wildcard URLs that resolve by specificity, declared head, static pages, forms that work without JavaScript, prerendering, and takeover by the browser app.                                                                                                                                                                                                                                                   |
| `islands`                    | agent-ui **as a library**, without its page model: a plain `node:http` host owns the page, renders two apps into it with `renderPage` and writes their state next to them; the browser loads the package's modules through an import map, with no build; `syncApps` sends the catalog's count to the header badge. A real-Chrome test.                                                                                                                                                                                                                                                                                |
| `production-server`          | A production host with no dependencies: Node's `http` serves the built files from memory (ETags, immutable hashed assets), `createSsrHandler` renders every page per request, security and CDN cache headers go on every answer, `/healthz`, graceful shutdown, and a Dockerfile.                                                                                                                                                                                                                                                                                                                                      |
| `with-express`               | agent-ui pages inside an Express server that owns the routes and the API.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `with-fastify`               | The same inside a Fastify server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `with-typescript`            | TypeScript and zod: one zod schema per kind of data gives the types (`z.infer`, checked with `tsc` and `checkJs`) and checks the answers of the resources (`response: Tasks.parse`) and the requests of the server.                                                                                                                                                                                                                                                                                                                                                                                                   |
| `with-tailwind`              | Tailwind CSS: utility classes in the spec, generated `pages/page.css`, a test that checks every class.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

## Run an example

From the repository root, one command per example. It installs the example, builds it and starts its server. Stop it with Ctrl+C. The install is a local link to the framework, so there is no network for the first twelve.

| Example                    | Command                                         | Then open              |
| -------------------------- | ----------------------------------------------- | ---------------------- |
| basic                      | `npm run example -- basic`                      | http://localhost:8080/ |
| notes                      | `npm run example -- notes`                      | http://localhost:8080/ |
| contacts                   | `npm run example -- contacts`                   | http://localhost:8080/ |
| todomvc                    | `npm run example -- todomvc`                    | http://localhost:8080/ |
| directory                  | `npm run example -- directory`                  | http://localhost:8080/ |
| hydration                  | `npm run example -- hydration`                  | http://localhost:8080/ |
| registration               | `npm run example -- registration`               | http://localhost:8080/ |
| loading-states             | `npm run example -- loading-states`             | http://localhost:8080/ |
| orders                     | `npm run example -- orders`                     | http://localhost:8080/ |
| shop                       | `npm run example -- shop`                       | http://localhost:8080/ |
| islands                    | `npm run example -- islands`                    | http://localhost:3000/ |
| production-server          | `npm run example -- production-server`          | http://localhost:8080/ |
| events                     | `npm run example -- events`                     | http://localhost:8080/ |
| with-express               | `npm run example -- with-express`               | http://localhost:3000/ |
| with-fastify               | `npm run example -- with-fastify`               | http://localhost:3000/ |
| with-tailwind              | `npm run example -- with-tailwind`              | http://localhost:8080/ |
| with-typescript            | `npm run example -- with-typescript`            | http://localhost:8080/ |
| react-converted-components | `npm run example -- react-converted-components` | http://localhost:8080/ |

`events`, `with-express`, `with-fastify`, `with-tailwind`, `with-typescript` and `react-converted-components` come last because they need the npm registry: `events` installs esbuild (its production minifier, see `docs/BUILD.md`, `transform`), the others Express, Fastify, the Tailwind CLI, TypeScript and zod, and Chart.js. `npm run example -- <name> <script>` runs any other script of an example (`test`, `build`, `dev`, ...), for instance `npm run example -- events test`.

Inside an example folder the same thing is `npm install && npm start`. Under the hood `start` is `agent-ui build` followed by `agent-ui serve` (pages rendered per request) or the example's own server (`node server.js`); `islands` has no build and starts its server directly.

`npm run test:examples`, which is part of `npm test`, installs and tests every example that needs nothing from the npm registry. `node test/run-examples.mjs --all` also runs `events`, `with-express`, `with-fastify`, `with-tailwind`, `with-typescript` and `react-converted-components`. Those six install esbuild, Express, Fastify, the Tailwind CLI, TypeScript and zod, and Chart.js, so they need network access. Until the packages are installed, their own tests skip the parts that need them.
